# RJNX architecture

App Router server components read Drizzle/PostgreSQL directly. Interactive forms post same-origin JSON to Next route handlers with Zod validation, CSRF checks, PostgreSQL-backed rate limits, and role checks. React never receives service credentials or other players’ room details. Supabase Auth owns hosted credentials, identity verification and recovery; app role rows are never derived from editable auth metadata. Local development uses real salted credentials and expiring hashed sessions on loopback only. Production Vercel does not permit local auth fallback.

Public DB data is selected explicitly. The isolated `rjnx` schema is not part of the Data API; all tables enable RLS. The application role’s server-only pool uses explicit owner checks with controlled grants. Media lives in a private Storage bucket in production; the server authorizes images and proofs. Local media uses PostgreSQL bytes.

Tournament mutations lock the tournament first, then related records. Capacity counts pending and approved entries; the roster is frozen at entry. A match can only use approved entries, and private credentials require an approved assigned roster member or management staff. Scoring rules are versioned by tournament configuration; results become public only after Admin verification, and corrections create revisions and retract previous standings until republished. Leaderboards aggregate verified results rather than storing duplicate totals. Ranking orders points, wins, kills, identifier. A tournament’s declared competition format guides staff scheduling; brackets aren’t automatically generated.

RBAC: Super Admin manages staff and players. Admin can manage players, platform settings, content and all tournaments, and verify results. Manager creates games/events, manages registration, schedules matches, and submits results but cannot publish results. Moderator handles teams and reports. Player manages their own profile and team, requests entry, and reads only their competitions and notifications. Sensitive mutations are audited without passwords or room credentials.
